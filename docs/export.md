# 匯出：token 與型別契約

把 theme 的 token 與 kit 的 props 交給工具鏈之外的世界。
**獨立模組，不改動 `wfyaml.py` 的行為**，渲染與 lint 完全不受影響。

> 這份內容適合併入 README（放在 `--debug` 那一節之前）；獨立成檔只是為了讓這個 PR 好 review。

```bash
python3 wfexport.py tokens themes/x.yaml                 # DTCG .tokens.json（預設）
python3 wfexport.py tokens themes/x.yaml --format css    # :root{--wf-*}
python3 wfexport.py tokens themes/x.yaml --format ts     # export const tokens
python3 wfexport.py types  kit/components.yaml           # TS 型別契約
python3 wfexport.py types  kit/components.yaml --types-map kit/prop-types.yaml
```

## tokens：對齊 DTCG

輸出遵循 [Design Tokens Community Group](https://www.designtokens.org/) 標準，
可直接餵 Style Dictionary（v4 起原生支援）或 Terrazzo 產各平台變數。
**書寫層維持現在的簡潔形式，標準只出現在輸出層** —— DTCG 是交換格式，
手寫時每個值要多兩層巢狀，diff 會變得難讀。

別名語法 `{family.name}` 與 DTCG 相同，匯出時原樣保留、不展開，型別由被參照的 token 決定。

| theme 家族 / 值的形狀 | DTCG `$type` |
| --- | --- |
| `color:` 家族、`#RRGGBB` | `color` |
| `12px` / `1.5rem` | `dimension`（標準只允許這兩種單位） |
| `150ms` / `1.5s` | `duration` |
| 四個數字的陣列 | `cubicBezier`（x 座標須在 0–1） |
| `font.body`、字串陣列 | `fontFamily` |
| `font.weight`：1–1000 或標準別名 | `fontWeight` |
| 無單位數值 | `number` |

同一家族內型別一致時 `$type` 提到群組層（DTCG §6.3），輸出較短好讀。
`tokens.preset` 不是 token，不匯出。

對不上標準型別的值（例如 `shadow: '0 4px 0 #2B2A33'`）**不會被猜著匯出**，
而是略過並在 stderr 說明原因：

```
warning: tokens.shadow.md 未匯出 —— 無對應的 DTCG 型別（'0 4px 0 #2B2A33'）
```

複合型（`shadow` / `border` / `transition` / `typography`）之後再依標準的結構支援。
先輸出合規的一半，好過輸出不合規的全部。

## types：契約而非實作

`props` 與 `states` 編成型別宣告。交付 RD 的是介面 —— 接上資料與行為是他們那一層的事，
所以這裡**不產生實作**，也就沒有「生成的程式碼我不想改但又不得不改」的問題。

型別標註放在選配的 sidecar 檔（`wfyaml.py` 的 kit 只認名稱 list，不受影響）：

```yaml
# kit/prop-types.yaml
stamp-card: { visits: number, tone: [info, warn] }
```

```ts
// generated by wfexport.py types --format ts, do not edit
export type StampCardProps = {
  place: string;          // 未標註者一律 string
  visits: number;
  tone: "info" | "warn";
  state?: "done" | "next" | "todo";
  to?: string;            // 動線目標（畫面 id）
};
```

型別只有 `text` / `number` / `boolean` / `date` / `time` / `url` 與 enum list。
刻意不提供物件、陣列、泛型 —— 那些是應用層的資料形狀，不是 UI 契約，
一旦開放，資料模型就會開始往 DSL 裡長。

sidecar 會被驗證：型別不合法、指到不存在的 props 或元件，都會直接報錯。

## 後續

若日後 `wfyaml.py` 的 kit 願意接受 `props: {名稱: 型別}`，
sidecar 就可以退場、改讀 kit 本身；本模組的輸出格式不會變。
